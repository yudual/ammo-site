# 知识库审查问题沉淀

这个文件专门记录每次知识库审查发现的问题。

目的不是追责，而是把错误变成后续规则，避免 Codex 或 Antigravity 下次再犯。

## 使用规则

每次知识库审查后，如果出现 `基本合格但需修` 或 `不合格`，都要追加记录。

每条记录至少写：

- 日期。
- 来源：Codex / Antigravity / 其他。
- 文件。
- 审查结论：合格 / 基本合格需修 / 不合格。
- 主要问题。
- 应沉淀规则。
- 后续检查口径。

如果问题已经补进 `SHARED_CODEX_ANTIGRAVITY_RULES.md` 或 `ANTIGRAVITY_KNOWLEDGE_POOL_WORKFLOW.md`，也要写明。

## 问题记录

### 2026-07-04 Codex 审查条目：2026-07-02 企业专项批次

- 来源：Codex
- 文件：
  - `batches/enterprise/enterprise-scout-2026-07-02-1940.md`
  - `raw-json/enterprise-scout-2026-07-02-1940.raw.json`
- 审查结论：基本合格需修
- 主要问题：
  - 招聘入口曾直接写成官网首页，无法追到具体招聘页面。
  - 个别来源标题和 URL 不匹配，容易让后续 clean JSON 误判为具体页已核实。
  - 这类批次虽然方向和主体都对，但来源粒度不够细，会影响后续转 clean 的效率。
- 应沉淀规则：
  - 招聘入口、招聘公告、学校就业网来源必须尽量指向具体页面，不得用首页顶替。
  - 标题、类型、日期、URL 四项必须成组校验，不能只看“是不是同一主体”。
  - 只要后续要转 clean JSON，就优先补具体页，不要把首页当万能占位。
- 后续检查口径：
  - 审查知识池企业批次时，优先检查 `招聘入口 / 招聘公告` 是否是具体页面。
  - 审查时，标题和 URL 不一致的，默认降级为需修。
  - 审查时，首页只可作为官网入口，不可混充多个来源。
